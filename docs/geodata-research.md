# 濮院时尚古镇真实地理底稿调查

日期：2026-11-17。目的：为手绘地图建立可追溯的真实地理骨架，判断现有公开资料是否足以完成定位配准。

## 已取得的结果

**已经取得真实 WGS84 地理数据：景区范围 polygon、部分道路/桥梁、水道中心线及具名 POI。还不足以完成全园建筑、水面重建，或证明当前美术示意图的定位准确。**

数据来自 OpenStreetMap 自身的 Nominatim 与 API，下载的是一次小范围矢量数据，不是地图瓦片。原始快照与可重复生成的 GeoJSON 均保存在 [`references/geodata/`](../references/geodata/README.md)。本轮没有修改应用地图或为现有美术图伪造 GPS 映射。

### 景区范围

[OSM way 1283631045](https://www.openstreetmap.org/way/1283631045) 的名称是“濮院时尚古镇”，标签为 `tourism=theme_park`。其闭合 polygon 有 62 个不同顶点，way 版本 1 的更新时间为 2024-05-16。节点拥有各自版本和时间，原始资料完整保留。

Nominatim 返回的包围框：

| 范围 | WGS84 数值 |
| --- | --- |
| 西侧经度 / west longitude | 120.6243733 |
| 东侧经度 / east longitude | 120.6342434 |
| 南侧纬度 / south latitude | 30.6789153 |
| 北侧纬度 / north latitude | 30.6862845 |

Nominatim 的代表点为 `[120.6296382, 30.6828922]`（经度、纬度）。该点只是地理索引的代表位置，**不是入口、GPS 控制点或可站立位置的保证**。景区 polygon 也是 OSM 社区标注，尚未获得景区方对运营范围的确认。

### 道路、水系、建筑

对景区包围框稍作外扩后，OSM API 返回 988 nodes、150 ways、41 relations。派生层具体包括：

| 几何 | 已取得 | 可用于什么 | 缺口 |
| --- | --- | --- | --- |
| 景区边界 | 1 个 polygon | 下一轮地图范围初稿、调查范围 | 官方边界及当前开放区域未确认。 |
| 道路/广场 | 125 个 highway ways，其中 pedestrian 62 个；包含园外路段 | 步行街和桥梁布局的初稿 | 完整性、路宽、通行限制、出入口、无障碍情况未现场核实。 |
| 水道 | 15 个 canal ways | 水系中心线和桥梁相对位置 | 没有水面 polygon，不能据中心线臆定河岸与宽度。 |
| 建筑 | 1 个 building polygon | 仅该对象的参考 | 明显无法覆盖园区大量建筑；缺 footprint、高度、屋顶及入口。 |
| 具名节点 | 8 个非公交 POI | 地名核对与后续实测候选 | 名称、位置和当前用途尚未获景区官方确认。 |

OSM 道路中可见观前街、寺湾街、蜡烛街、乐里街；桥梁包括大有桥、北廊桥、永乐桥、御桥、香烛桥、碧水桥等。这些是可追溯的原始标签，不应自动等同于参考图或演示活动数据中的同名/近似名地点。

数据请求框为 `[120.6240, 30.6785, 120.6347, 30.6867]`，按 west/south/east/north 顺序。它不是景区边界；返回的 way 可能跨出范围。派生层未进行景区裁剪，41 个 relation 没有强行拼装成不完整 polygon。

## 对下一步实现的建议

1. 用 `boundary.geojson`、`roads.geojson` 和 `waterways.geojson` 构建真正以地理位置为底的白模，而不是把经纬度线性缩放到当前自由绘制的美术图。
2. 使用节点 ID 和原始名称作为核对线索，逐项确认演示地点与真实 POI 是否对应。不能因为名字相似便自动匹配。
3. 补充园区建筑 footprint、河岸、水面及出入口。最直接的输入仍是景区总平面 CAD/GIS（需坐标系说明），或获得授权的测绘成果；OSM 当前覆盖不足。
4. 在多个桥头、入口、路口取得独立实测点，分别评估底图配准与设备定位误差。点位应分布在全园，保留一部分只用于验收，不用于拟合。
5. 确认真实地理白模后，再按其道路和建筑 footprint 制作固定视角 2.5D 美术；pin 与用户位置使用同一地理坐标链路。

当前产品可以继续呈现明确标注的美术示意地图。真实定位不能仅靠这次找到的包围框或代表点就“贴上去”；所需工作是**重建地理正确的地图并验证配准**。

## 来源、许可与调查局限

- 主要数据来源：[OSM 地物页](https://www.openstreetmap.org/way/1283631045)、[way 完整 JSON](https://api.openstreetmap.org/api/0.6/way/1283631045/full.json)、[小范围原始 JSON](https://api.openstreetmap.org/api/0.6/map.json?bbox=120.6240,30.6785,120.6347,30.6867)。本轮均实际读取成功。
- Nominatim 原始响应包含 `Data © OpenStreetMap contributors, ODbL 1.0`；保存的派生 GeoJSON 也保留 attribution 和 license。采用这些数据时，需要按 [OSM 署名及许可说明](https://www.openstreetmap.org/copyright) 处理署名与衍生数据库要求。
- 一次中文全名查询确认了浙江省嘉兴市桐乡市濮院镇的目标景区，避免与“浦源镇”“璞园”等同音地点混淆。
- Overpass 主站返回 406，另两个镜像超时，因此改用 OSM 官方 API 获取同一区域。没有批量遍历下载，没有抓商业地图图片。
- 本轮官方景区网站搜索没有取得可验证的权威地理文件。没有声称已获得景区官方边界、完整建筑或真实活动运营资料。
- 尚未现场测量，尚未与官方底图交叉验证，也未将这些数据接入应用。数据覆盖和地图质量需要独立验收。
