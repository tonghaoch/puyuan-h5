# 微信 H5、地理坐标与手绘地图：技术核对

核对日期：2026-11-17。本文记录平台事实和项目建议；平台事实附官方来源，建议不代表已经完成真机验证。

已确认的产品方向：只重塑古镇内部；真实地理布局优先；中式复古、古风游戏建筑；固定视角 2.5D，可拖动缩放，并有局部动画。

## 结论

推荐以 **WGS84 地理数据 + MapLibre GL JS + 预渲染手绘地图/建筑 + 少量独立动画层** 起步。微信内显式请求 `wx.getLocation({ type: 'wgs84' })`；浏览器定位通过独立 adapter 接入。地图、地点、用户位置必须使用同一坐标约定。

现有图片只有视觉参考价值，尚无已核实的园区边界、道路、建筑 footprint 或控制点经纬度。图片不是带地理参考的正射图。**不能依据图片上的相对位置编造“精确坐标”**，也不能用四角拉伸或地图投影解决图内不同区域的比例和透视变化。地图资产制作前，需要取得有来源和坐标系说明的园区底图，并用现场控制点检验。

这里的推荐基于地图只覆盖一个园区、需要高度定制美术的产品条件。如果后续主要依赖高德的 POI、路线和底图，应重新评估使用高德 SDK，并把其展示链路统一为 GCJ-02。商业地图的数据获取和再利用范围必须按选定产品的授权处理，不能默认把在线底图抓取后重绘成自有数据。[6][7]

## 微信 JS-SDK：已核实

| 事项 | 官方说明 | 本项目处理 |
| --- | --- | --- |
| 能力可用性 | 可用接口随账号类型和认证状态而不同，需要在后台查看权限。[1] | 接入前确认目标账号实际具有 `getLocation` 等接口权限；不把“有 appId”当作已具备权限。 |
| 域名 | 配置“JS接口安全域名”；当前文档说明域名需通过 ICP 备案验证，不支持 IP、端口号、短链域名。[2] | 开发服务器可以用于页面开发，微信正式定位联调另备满足条件的 HTTPS 域名。不要混淆 JS 接口安全域名与网页授权域名。 |
| 初始化 | `wx.config` 注入 `appId`、`timestamp`、`nonceStr`、`signature`、`jsApiList`；通过 `ready`/`error` 处理结果。[2] | 微信能力由专门 module 管理，业务页面不重复处理初始化和签名。 |
| 签名 | 对 `noncestr`、`jsapi_ticket`、`timestamp`、完整 URL 排序并计算 SHA-1；URL 不包含 `#` 及其后面内容。必须在服务端签名。[2] | 小型后端提供签名接口，校验请求页面的协议和域名；appSecret、access_token、ticket 不下发前端。 |
| 凭据缓存 | 官方要求服务端全局缓存 access_token 与 jsapi_ticket；文档给出的通常有效期为 7200 秒。[2] | 按返回的 `expires_in` 管理刷新和并发；不要每次用户打开页面都重新向微信申请 ticket。 |
| 定位坐标 | `getLocation` 默认 `wgs84`；可传 `gcj02`，用于微信 `openLocation` 的火星坐标。[2] | 参数显式填写并记录在结果中，禁止靠调用方猜测坐标系。 |
| 定位返回 | 文档列出纬度、经度、速度与 `accuracy`（位置精度）。[2] | 保存来源、坐标类型、精度原值和本地接收时间；微信例子未提供与浏览器完全相同的采样时间/精度语义。 |

签名接口是应用自己的后端，不要求用户为浏览地图先进行 OAuth 登录。需要的微信 JS-SDK 配置与用户身份登录是两个不同流程；以后有收藏、订票等身份功能时，再决定是否引入登录。

官方 iOS 文档确实记录过历史版本中 History API 与授权的兼容问题，但其内容涉及微信 6.5.x，不能据此宣称所有当前 iPhone 都必须用某个历史 workaround。[3] 建议第一版使用 hash 路由，让 tab 和详情切换不改变签名 URL 的主体；仍需用当前 iOS/Android 微信实测分享入口、返回、刷新以及路由切换。签名时保留完整 query，不随意解码、排序或重构 URL。[2]

## 定位与失败处理

浏览器 Geolocation 标准使用 WGS84，提供 `getCurrentPosition`、`watchPosition`、`maximumAge`、`timeout`、`enableHighAccuracy`、坐标精度和采样时间。需要安全上下文和用户授权；`enableHighAccuracy` 只是请求，浏览器可以忽略。[4]

建议采用以下行为：

1. 用户主动点击定位后，在微信且 SDK 就绪时优先使用微信定位；其他环境使用浏览器 Geolocation。
2. `getLocation` 是单次获取接口，不能按 `watchPosition` 持续监听的能力来设计。第一版先保证手动定位和更新可靠；连续跟随另做真机验证。
3. SDK 不可用或技术失败时，浏览器定位可以作为能力降级；用户明确拒绝定位时，不自动换另一通道重复索要权限。
4. 定位失败、超时、过期、精度过低、位于园区外分别建模。不能失败后把游客点放在园区中心，或把园外位置强制吸到园内道路。
5. 精度圆表现测量的不确定性，不承诺一定在圆内。微信 `accuracy` 文档表述较少，需要真机核实其数值含义；浏览器与微信精度不可不加区分地视为等价。[2][4]
6. 保存真实采样时间（浏览器可提供）或明确标记“接收时间”；显示旧位置时给出状态。页面切后台时停掉应用自己的更新循环，恢复后重新判断数据是否过期。
7. 位置只用于当次本地展示和距离计算时，没有必要把轨迹上传到业务服务器。定位提示说明用途；不申请位置也能使用地图和列表。

必须区分两种误差：**地图配准误差**与**手机定位误差**。前者靠底图和现场测点校验解决，后者受设备、遮挡、网络和平台实现影响。不能仅靠地图绘制精细或经纬度小数位数，承诺游客点达到米级精度。

## 坐标与地理数据

| 数据 | 推荐约定 |
| --- | --- |
| 自有地点、园区边界、道路、水系、建筑 footprint | 明确标为 WGS84；GeoJSON 坐标顺序为 `[longitude, latitude]`。保留原始资料及来源。 |
| 微信定位 | 显式请求 `wgs84`；如果后续外部接口需要 `gcj02`，在明确的 adapter 处处理。 |
| 浏览器定位 | 按标准返回 WGS84；真机对照控制点，排查厂商实现差异。[4] |
| 高德 POI/地图 | 高德官方说明其坐标为 GCJ-02，GPS 等其他坐标需要转换后匹配高德地图。[6] 不将其结果重新贴上 WGS84 标签。 |
| 地图瓦片/渲染 | MapLibre sources 规范按 global/Spherical Mercator 处理常用瓦片；EPSG:3857 是投影坐标，不能把“投影转换”当作 WGS84 与 GCJ-02 的转换。[5] |

数据流建议：

```text
有来源、坐标系已知的地理资料
        ↓ 导入、必要转换、地面控制点校验
WGS84 园区数据 ──→ MapLibre 固定镜头 ──→ 屏幕位置
        ↑                  ↑
地点/入口真实坐标       wx / browser 定位（WGS84）
```

一个地点至少区分建筑/活动区域与游客可到达的入口。pin 可以有视觉偏移，但距离计算和以后路线终点使用入口坐标。统一位置对象应保留坐标系、来源和核实状态；未经测量的数据标记待核实，不作为定位验收依据。

具体园区中心、边界、控制点和地点经纬度本轮没有权威数据支持，本文不填写。建议取得景区 CAD/GIS 总平面图、坐标参照说明和实测入口/桥头等控制点；仅有商业地图坐标时，先确认坐标类型及允许的使用范围。

## 固定视角 2.5D 与动画

MapLibre 的 image source 支持为图像指定四个角的经纬度，按左上、右上、右下、左下顺时针排列；raster source 支持瓦片。规范也包含 GeoJSON 数据源、聚合和 attribution。[5] 这说明可以把**已经配准的地图资产**放入地图引擎；不代表把任意插画提供四个角就能让内部所有位置准确。

推荐的美术和渲染拆分：

- 地面层：真实的道路、水系、桥梁连接与建筑 footprint，建立在地理数据上。
- 建筑层：固定朝向的手绘屋顶、立面和装饰。可将有授权的古风游戏模型作为离线渲染输入，最终输出 2D 美术资产；入口位置与地面保持一致。
- 地图资产：先以小范围配准 image 验证，再按缩放等级切成栅格瓦片。文字、地点 pin 与位置点单独绘制，避免被烘焙进底图后无法交互或重复缩放。
- 动画层：水面、灯笼、烟雾、局部人物或建筑亮灯按需叠加，位置锚定地面或建筑。CSS/Canvas 能满足时先使用它们；是否引入 Pixi 等额外渲染栈，由样片压测决定。
- 交互层：MapLibre 处理镜头、坐标投影和地点拾取；详情面板和列表属于应用界面。

需要先验证“固定角度”的具体表达：`pitch=0`、固定朝向配合立面/屋顶美术，能在准确平面布局上产生 2.5D 观感；若要真正倾斜镜头，则整个离线美术流程必须与该镜头一致。**不能把已经带斜透视的整张建筑图再随意增加地图 pitch**，否则出现二次倾斜及锚点漂移。用一座建筑、一座桥、一个路口先做小样，并检查多级缩放中的地面锚点和遮挡。

定位点和关键 pin 不能被高建筑美术挡住。建筑屋顶可视觉夸张，建筑 footprint、入口、道路宽度和桥头连接不要随之改变。热区依据地点/区域地理几何定义，不依赖插画像素猜测。

动画策略属于工程建议，尚未性能验证：只播放可见区域，远景降低细节，拖动缩放时降低粒子数量，页面隐藏时暂停，支持减少动态效果偏好和低性能设备降级。不要预设微信 WebView 能稳定运行全图实时 3D 或大量独立动画。

## 数据来源和平台选型边界

- 高德现行服务协议涉及商业用途许可、数据存储/抓取及再利用范围、标识展示等要求。[7] 它是可选地图产品，不应当被当成无条件可抓取的建筑数据源。本项目若采用其产品，需要按实际主体与用途确认相应套餐和授权。
- OpenStreetMap 公共瓦片服务没有 SLA，要求署名，禁止批量预抓及离线下载；不能因为 OSM 数据开放，就把其公共瓦片服务器当成无限制的生产 CDN。[8] OSM 建筑数据是否覆盖濮院园区、更新是否及时，本轮未验证。
- 自有手绘资产可以通过适合目标用户网络的静态托管/CDN 分发。MapLibre 是渲染选择，底图、字体、图标、瓦片来源和版权依然要分别选定。

## 实施前需要验证的项目

1. 取得园区真实地理底图并确认哪些入口、设施属于开放区域；用分布在园区内外缘的独立测点检查配准，检验点不要全部用于拟合。
2. 确认微信账号接口权限与联调域名；实现最小签名链路并在 iOS/Android 微信各测一次定位。
3. 建立小范围 2.5D 样片，验证美术与真实地面坐标一致，以及建筑遮挡、pin 命中和位置点显示。
4. 用目标机型检查首屏传输量、贴图内存、拖缩帧率和动画开销。精度、性能目标在原型测量后定值，不在此虚构验收结果。
