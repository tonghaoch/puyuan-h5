# 美术与动画技术方向

状态：技术与素材约束。第一版已有程序绘制的示意地图与 UI，当前实现见 [实现记录](implementation.md)；最终地标美术尚未完成。用户已确认真实地理布局优先、中式复古、华丽的古风游戏式 2.5D，以及较丰富的局部动画。

## 1. 画面构成

画面以古镇为主体：江南水巷、瓦顶、木构、院落、石桥、灯影与植被。重点地标可以具有更精细的屋檐、纹饰、灯光和材质。整体保留地理关系，局部丰富度随缩放增加。

界面可探索古铜、木色、绢纸、墨色与少量朱砂/金色点缀，但颜色、字体、边框、图标、按钮和弹层在 UI 阶段再定。正文和营业信息优先可读，装饰字只用于适合的短标题。

“华丽”主要由建筑细节、材质、景深层次、灯光和有节奏的动画共同形成，不要求手机实时计算复杂三维场景。

## 2. 素材管线

### 现成模型与自制资产

已有的游戏模型、贴图和动画可作为美术输入。输入后先检查格式、贴图、单位、轴向、骨骼、材质和着色器依赖，再统一风格。FBX/glTF 等是素材中间格式，不能假设任意游戏包都能直接被浏览器加载。

建筑主体推荐在 Blender 等工具中设置统一镜头和光照，离线渲染为带透明通道的图像，再与地理地面层合成。河流、道路、桥面以及建筑落地点保持准确；屋顶和立面可有视觉偏移。地面投影与固定视角的配合必须先通过样片验证。

重点建筑单独制作，普通建筑使用屋顶、门楼、墙面和植物素材库组合，减少重复制作。真实地标不能被通用古风楼阁完全替代，否则地图无法帮助游客识别现场。

如后续需要 AI 生成素材，用它提供纹理、装饰、建筑细节或独立素材，并人工配准到已确定的地理底稿。不能用一张 AI 生成的完整古镇图承担准确定位。

### 交付格式

- 静态主体：WebP/PNG 作为制作交付格式，进一步合成为分级地图瓦片；保留原始工程与透明素材。
- 交互区域：GeoJSON 保存地点、入口与建筑地面轮廓。
- 简单运动：CSS/SVG 表现 pin、选中态与小型交互效果。
- 复杂局部运动：短循环 sprite 图集或 Canvas；按需要加载和播放。高密度精灵效果再评估 PixiJS。
- 字体：仅加载必要字重，并按实际文字集做子集处理，避免完整大字库阻塞首屏。
- 地图 manifest：记录素材版本、坐标体系、覆盖范围、缩放级别和动效锚点。

先确保模型外观与光照统一，再做切图。切图要检查透明边缘、瓦片接缝、不同缩放层的建筑跳变，以及高像素密度屏幕上的清晰度。

## 3. 动画分层

| 层 | 示例 | 播放规则 |
| --- | --- | --- |
| 交互反馈 | pin 轻弹、选中光圈、详情展开、镜头平移 | 短时、可中断，优先响应操作 |
| 环境氛围 | 水纹、树影、灯笼、烟雾、局部灯光 | 缓慢循环，只播放当前视野内的部分 |
| 活动提示 | 正在演出的光效、活动点附近少量粒子 | 绑定真实活动状态，避免全地图同时闪动 |
| 地标演出 | 一个水面效果或一处建筑的短循环 | 按需加载，近距离再启用 |

第一版先制作一小段水面、一组灯笼和一个活动 pin，验证风格与帧率，再扩大数量。动画应让人感受到环境变化，并帮助理解活动状态。

不使用整图 GIF，也不为每栋楼创建视频播放器。水面效果需要遮罩，避免流到岸上；植物、建筑、烟雾的前后关系由统一图层顺序控制。

## 4. 地理层与视觉层

从下到上的基本顺序：地面水系与道路、静态建筑、环境动效、地点标签与 pins、用户位置及精度提示、产品界面。特殊遮挡在素材阶段解决，不改变真实位置坐标。

地图镜头是唯一的移动与缩放依据。动效锚点都保存为地图地理位置，并使用同一镜头投影到屏幕；不要各自维护一套拖动偏移。pin 的指向点落在入口，图标本身可以向上偏移以避开屋檐。

缩小时保留主要地标、活动与必要标签，减少细碎纹理和粒子；放大后逐渐显示院落细节、设施和装饰。标签与点击区域保持适合手指操作的屏幕尺寸，不能与地理建筑尺寸机械同比缩小。

## 5. 微信性能预算

以下是样片阶段的目标，需要用指定的 iOS/Android 真机和实际网络测量，不作为已经达到的指标。

- 首次可交互所需的 JS、CSS、字体与首屏地图资源合计争取控制在 3 MB 左右；高分辨率瓦片、详情大图与额外动效随后加载。
- 中低档目标设备拖动与缩放尽量稳定在 30 FPS 以上，较新设备争取 60 FPS；判断依据包含掉帧和操作延迟，而非只看平均值。
- 第一版一个屏幕只启用少量持续动态区域；视野外、低缩放级别、详情遮挡较多、切换 tab 或进入后台时暂停不必要效果。
- 图集按设备支持的纹理尺寸拆分，避免一次解码整张超大透明图；限制设备像素比与图层缓存大小，处理 WebGL 上下文丢失。
- 定位、手势与详情打开优先于粒子数量；出现持续掉帧时自动降低效果密度。
- 提供减少动态效果的开关并尊重系统偏好，保留必要状态反馈。
- 音效不默认自动播放；如果以后需要，单独设计用户开启入口。

重点实测微信 WebView 的内存、热量、后台恢复、快速缩放、连续打开详情及长时间游览。先验证“小区域样片好看且流畅”，再投入全园资产制作。

## 6. UI 阶段要确定的内容

下一轮可选一至两个古风游戏作为视觉参考，围绕以下内容出方案：地图的建筑精细程度与色彩；白天或傍晚的基础氛围；pin 的材质与动效；底部三个 tab；地点/活动详情；餐厅与活动列表；定位点与精度范围。

当前第一版已实现统一的地图、列表与详情视觉；后续以地标样片继续提高建筑细节和素材品质。
