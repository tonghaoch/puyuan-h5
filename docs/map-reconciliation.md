# 原图、OSM 路网与真实影像的对应核对

调查日期：2026-11-17 至 2026-11-18。范围仅为用户提供的濮院导览图和濮院时尚古镇；未修改应用代码。

## 结论

**已经取得一张带真实地理范围的 Esri World Imagery 官方导出影像。影像与原图的总体水系和大型建筑布局存在明显对应，可以用于约束地图复刻。当前没有足够已确认的图像地面控制点，不能声称已将原图精确配准，也不能直接用包围框把游客定位贴到透视手绘图上。**

建议查看以下资料：

- [原始影像](../references/geodata/esri-world-imagery-reference.jpg)：1400 × 1200，北向上，地理范围见随附 export JSON。
- [影像与 OSM 叠加核对图](../references/geodata/esri-osm-comparison.jpg)：粉色景区边界、浅黄色道路、蓝色水道中心线、橙色桥梁。所有叠加数据均来自现有 OSM 快照，没有为了视觉效果补造几何。
- [原始导出结果](../references/geodata/esri-world-imagery-export.json)、[服务元数据](../references/geodata/esri-world-imagery-service.json)、[中心点影像来源元数据](../references/geodata/esri-world-imagery-local-metadata.json)。

## 影像取得方式与地理参考

公开调用一次官方 [World Imagery MapServer export](https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/export)，参数为：

```text
bbox=120.6240,30.6785,120.6347,30.6867
bboxSR=4326
imageSR=3857
size=1400,1200
format=jpg
f=json
```

服务器为了匹配图片宽高比返回了调整后的实际范围。因此叠加必须使用**返回的 extent**，而不是把请求 bbox 直接当图片四角：

| EPSG:3857 范围（米） | 返回值 |
| --- | --- |
| xmin | 13427778.661228307 |
| ymin | 3591066.258792900 |
| xmax | 13429016.972218843 |
| ymax | 3592127.668213361 |

返回的空间参考 `wkid=102100`、`latestWkid=3857`。原影像另附 [JGW world file](../references/geodata/esri-world-imagery-reference.jgw)，采用这个返回范围和像素中心约定；其坐标单位为 EPSG:3857 投影米。带底部说明条的 `esri-osm-comparison.jpg` 仅供目视核对，不能套用原影像的 JGW。

本轮只请求一次整图 export，没有下载/拼接商业地图切片，也没有绕过权限或凭据。调查完成后，主实现已将影像和原始返回 extent 接入本地 H5 的「影像核对」视图，用于与真实路网和 GPS 对照；尚未对外部署。

这表示**该中心点的服务元数据列出的来源日期为 2025-05-27**。本轮没有逐像素/分区查询覆盖，因此不能保证整张导出图同一天采集。`SRC_RES`、`SRC_ACC` 仅按服务原值保存，不将其解释为本项目或用户定位已经达到相应实测精度。服务完整更新时间未在本轮取得的资料中核实。

影像是目视核对参考，不是景区测绘交付。公开可调用不等于任意再分发或制作衍生资产的授权；如以后需要在应用中发布影像或依据影像生产商业地理数据库，按[服务说明所链接的使用条款](https://goto.arcgisonline.com/maps/World_Imagery)确认范围。OSM 数据仍按其自身的 ODbL 处理，不能把两者的授权混为一谈。

## 与原图的空间对应线索

目视对比原图与地理影像，可确认以下**总体布局相似性**；不把这些描述当作已经量化的地面控制点：

1. **北部水道与游客中心区**：原图游客中心南侧有廊桥跨水，真实影像北部也有建筑入口区及相邻跨水通道。OSM 北廊桥、游客中心点可帮助进一步调查。
2. **中央寺塔区**：原图高塔在寺院北侧，西侧沿河，东侧还有水面；真实影像和 OSM 两个节点显示相同的大体相对关系。塔身在透视插画上的顶点、底座、阴影是不同位置，不能拿塔顶直接映射 GPS。
3. **东北方形庭院建筑**：原图“禅意酒店”是明显方形庭院，真实影像东北部也有强烈对应的方形庭院体量。形态对应较强，但本轮未取得其官方名称、入口或建筑 footprint 数据，不能由此创建新的已确认 POI。
4. **寺院东侧弧端场地**：原图的长条、弧端场地与影像中的相似场地相邻关系一致。原图表现为绿色区域，影像呈硬质铺装；这至少表明颜色/用途表达不能被直接当作当前地面事实。
5. **东侧主河与分汊**：原图的主河道和狭长街区在影像中可辨认。原图水宽、岸线弯曲与部分河湾比例经过艺术表达；OSM 只有中心线，无法独立验证这些水面形状。
6. **西南大有桥一带与南侧道路**：原图该区域位于寺塔西南，OSM 大有桥也位于寺塔西南，南侧凯旋路/西侧中兴路构成可追溯的外部方向参照。原图大建筑群的位置与桥体锚点仍应分开。

原图包含建筑立面、屋顶抬高、标签遮挡和非统一局部比例，影像则是北向上的地理图像。总体拓扑相似不足以证明四角变换、统一缩放或单一仿射变换能满足全园定位。当前没有进行任意猜点拟合，也没有报告虚假的残差或“米级精度”。

## 路、河与桥的连接图

新增 [`osm-connectivity-review.json`](../references/geodata/osm-connectivity-review.json) 与 [`bridges.geojson`](../references/geodata/bridges.geojson)。连接关系只根据原始 OSM way 内相邻 node ID 构建，两个地理线段看起来相交时**不会自动产生连接**。道路和水系保持独立图。

| 图 | 节点 | 去重无向边 | 连通分量节点数 | 度数至少 3 的节点 |
| --- | --- | --- | --- | --- |
| 道路 | 412 | 454 | 407、5 | 91 |
| 水道 | 401 | 410 | 401 | 22 |

125 个道路 ways 中有 29 个 `bridge=yes`，已全部保留在 bridges 层。它们包含园外普通道路桥，尚未按景区裁剪。桥梁名称包括北廊桥、大有桥、鸣凤桥、永乐桥、御桥、香烛桥、碧水桥等，均保留 OSM 原文。道路的小连通分量来源为 `way/1283631060`，标签 `highway=unclassified`；本轮没有用推测连线“修复”它。

这是一张供核对的原始连接图，**不是可直接上线的步行导航图**：未解释单行、access、开放时间、桥梁通行条件、区域内部走法，也未进行实地验证。它能帮助复刻时保持“这条街跨哪条河、哪里确有桥”的结构，而不是装饰性地随意增加桥或河道。

## 可执行的复刻与定位处理

- 原图复刻阶段：保留可辨认的建筑群轮廓、岛块、水路分布和相互关系，用这张影像和 OSM 网络排查明显放错街区/断河/错桥的问题。
- 地理配准阶段：为少量跨全园分布的**地面**位置确认身份与真实坐标，例如桥头、入口门槛、路口；保留独立验收点。艺术建筑顶点和文字标签不作为控制点。
- 如果主地图继续采用原图式透视，用户定位应在经过验证的转换中放置；转换未经验证时，在独立的真实地理位置概览或主地图的真实路网/影像视图中展示位置，保持手绘图信息诚实。
- 若需要全园可验证的定位精度，仍需景区 CAD/GIS 或经过授权且检查过的地理底图、现场控制点及设备定位测试。本轮成果降低了地理信息缺失，不能代替这些验证。

复现文件生成方式：执行 `python3 references/geodata/reconcile-references.py`。脚本读取保存的原始快照与 Esri export 元数据，生成连接图、桥梁层、影像叠加图和原图 JGW；不访问网络，也不新增地理点。
