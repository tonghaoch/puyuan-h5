# 手机测试与分享审阅

## 用自己的手机先测，不需要 GitHub Pages

1. 手机和 Mac 连同一可信 Wi-Fi；在仓库根目录运行 `npm ci`（已装依赖可跳过），再运行 `npm run wechat:preview -- --lan`。这会构建 H5，将网页成品绑定到一个局域网 IPv4 的 4174 端口，并把含随机访问码的地址写入本机小程序壳。不带 `--lan` 时仅监听本机，供开发者工具模拟器使用。
2. 将终端显示的**完整链接**发给自己的微信，在手机里点开。没有随机路径会返回 404；链接持有人在同一网络可查看行程和活动照片，HTTP 不加密，请不要转发或在公共 Wi-Fi 使用。终端须保持运行，结束时按 Ctrl-C；重新启动会换码。手机里的 `localhost` 是手机自己，不是电脑。如果连不上，检查 Wi-Fi 设备隔离、macOS 防火墙和 VPN；多网卡可用 `WECHAT_LAN_IP=实际的Wi-Fi地址 npm run wechat:preview -- --lan`。
3. 打开**微信开发者工具 → 小程序 → 导入**，选仓库根目录（有 `project.config.json`），不是 `src/`、`dist/` 或 `miniprogram/`。用该 AppID 的开发者微信登录；若不属于该项目，请换成有权限的非个人主体小程序 AppID。`miniprogramRoot` 只打包轻量壳，不会打包整套地图。
4. 临时局域网调试可在**详情 → 本地设置**勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。点**编译 → 真机调试**（或「预览」），用同一开发者微信扫码。若开发版提示域名不可用，可在手机开发版菜单开启调试、退出并重新进入；不同客户端/账号仍可能拒绝局域网 HTTP。这是调试手段，不是发布配置。
5. 局域网打不开 `web-view`、需要验证定位，或要跨网络测试时，**改用已配置业务域名的 HTTPS 站点**：运行 `npm run wechat:preview -- https://你的域名/站点路径/`，再编译、重新扫码。此模式不启动本机服务器。退出本地「不校验」后再验证一次。

**正式版与体验版**：在小程序管理后台的开发设置配置 **业务域名**（不是 request 合法域名），按微信要求完成域名资质与校验文件验证。个人类型小程序不支持 `web-view`。GitHub Pages 可用于普通微信网页审阅，但 `github.io` 地址不等于已获准的小程序业务域名。真机扫码及定位授权需本人完成；定位使用浏览器 Geolocation，未接入微信 JS-SDK，HTTP 局域网页面不能用来验收定位能力。

[微信官方 web-view 说明](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html) · [网络与开发调试说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

## 定位验收

真实定位验收请在手机微信用受信任的 **HTTPS 测试部署**打开普通导览，不要使用局域网 HTTP 或模拟步行链接。园内有覆盖时，手绘图自动显示「约位」；点右下角「我的位置」，应停留在原视野：园内显示角落边界小图和精度圈，园外只显示提示。地图仍可拖动、缩放，点原按钮可收起。走动、切后台再返回，检查位置更新；拒绝授权不影响浏览，可在提示中手动重试。

定位 UI 的本地验收：启动 `npm run dev`，在开发地址后加 `?preview=walk`。靛蓝圆印是模拟位置，不会读取设备 GPS。点「模拟步行」可暂停或继续；系统开启减少动态效果时改为手动单步。拖动或缩放后，点右下角定位键可回到圆印，当前缩放倍数不变。单独构建手机 UI 预览时使用 Vite 的 `--mode location-preview`；常规构建和 Pages 即使带上相同参数也不启用模拟。

### 手绘图局部配准：东河水街（第三轮）

在仓库根目录运行 `python3 scripts/review_location_registration.py`（依赖 Pillow，无需网络）。双击生成的 `artifacts/location-calibration/review.html`，先看 H1 御桥，切换「显示预测点和偏移线」对比桥心与落点。旁边的 `report.json` 列出各点的参考经纬度、预测画布坐标、像素偏差和地面等效偏差。两份产物均只用于本地验收，不进入 Pages。

[原始配对](../references/geodata/east-water-street-registration.json)区分 4 个拟合地标和 3 个未参与拟合的验收桥心。卫星像素使用原始导出影像的 JGW 像素中心；插画像素使用最终 1520 × 1240 画布，不重复加偏移。用最小二乘拟合局部仿射，将残差通过其线性部分逆算回影像像素，再按 JGW 和当地纬度换算成近似地面米。OSM 桥梁编号只辅助辨认，不把活动标记、地名或屋顶当作地面测点。

三处独立偏差分别为 **御桥 7.5 米、东侧南北巷小桥 3.3 米、南斜街桥 4.3 米**。本轮不通过：即使不计设备自身误差，御桥的预测也落到了桥面外。该模型不进入应用，不外推到全园。下轮若安排现场采点，应另留未参与调参的检查点；本轮未进行现场测量。

### 手绘约位：在家验收

**验收手机朝向**：运行 `npm run location:review`，打开 `artifacts/location-calibration/coverage.html`，在「在家模拟」选 **H2**。保持地标不变，将「模拟手机朝向」从 0°（北）拖到 90°（东）：扇尖应随之转向，圆心和底图不动。这里模拟的是手机屏幕上沿，不是行走路线；不读取传感器。

**真机使用**：园内有定位点时，手机放平，原地左右转动。若设备需要额外授权，点右下角定位键，在角落小图点「开启手机朝向」。两张图的扇尖指向同一地理方向，手绘图会按当前位置的画法换算角度。不支持指南针、拒绝授权、数据过期或朝向不可靠时只画位置；地图不跟着转。磁性手机壳、附近金属和微信版本都可能影响读数；朝向仅供辨向，不作导航。

在仓库根目录运行 `npm run location:review`（Node 见 `.nvmrc`，Python 需 Pillow，不用联网）。打开 `artifacts/location-calibration/coverage.html`。青色是实际应用在给定设备精度下会画点的地理范围。选择 **H2 东侧南北巷小桥**看手绘落点和圈；再选 **V6 南街西段**，应只显示「仅园区小图」。页面不读取你的定位，可点「逐点卫星／插画对照」查看认点依据。逐点数值在同目录 `park-report.json`。验收页不进 Pages。

- **配准方法**：以 Esri 卫星图原始 JGW 像素中心和最终 1520 × 1240 画布配对，不用活动坐标、POI 标签、塔尖或屋顶推算地面。23 个控制点；比较整图仿射、5 种平滑量的薄板样条和 Delaunay 分片仿射。先要求任何已知地标不被移走超过 4 个画布像素，再按 12 个有邻域支撑的留一预测选择。三角网胜出，37 个三角形方向均正常。御桥 H1 已转为控制点，不能再用它证明精度。
- **误差和覆盖分开计**：8 个未参与拟合的点用于筛查区域。可用的 6 点地面等效 RMS 3.9 米（相同六点整图仿射为 9.0 米）。东侧河岛 66.3 米、南部水街 31.0 米，没有从报告中删掉，周边改用地理小图。H2 比旧局部仿射更准（3.3 → 1.3 米）；H3 略差（4.3 → 5.2 米），没有每座桥都变准。
- **另留 4 点最后核验**：F1–F4 不参与拟合、模型选择、误差圈或覆盖筛选。模型覆盖内 3 点为 8.0、1.6、9.4 米，RMS **7.2 米**；覆盖外 F3 为 18.2 米。若不区分覆盖，四点 RMS 11.0 米。这是影像对照，不是手机 GPS 保证，样本少，不能外推全园。
- **显示规则**：读取浏览器 WGS84，经 Web Mercator 和原始 JGW 换算，不对来源不明的坐标盲加 GCJ-02 偏移。位置必须新鲜、确认在公开园界内且设备报告精度 ≤50 米。将设备精度加影像标称 5 米作为安全边距，要求整圈留在控制点包围区、距最近控制点不超过 170 影像像素且不进入筛查失败点的 170 像素邻域。图上圈另加保留筛查点和留一结果中的最大误差（取整 16 米），再按附近三角形最大方向放大率绘制；它不是统计置信区间。不显示时不沿用上一次的手绘点。
- **实际显示面积**：按公开园界每 5 个影像像素取样，用正式 H5 的园界判断和投影代码计算。设备报告 5 / 10 / 30 米时，分别约有 **52.0% / 48.7% / 34.0%** 的园区面积会画约位，不代表可步行路线的覆盖率。边缘即便有地标，读数范围跨出支持区也会退回小图。
- **维护**：配对保存在 `references/geodata/park-registration.json`。改动后运行 `python3 -B scripts/calibrate_illustration.py --write-model` 重建 `src/data/illustration-registration.json`，然后重新验收。若使用本轮 F 点调参，应另留新的验收地标。

## 给同事一个 GitHub Pages 链接


- `npm run build:review` 生成 `dist-review/`。它是可独立部署的静态站点，支持仓库子路径和 `#map` 等深链接。不要上传整个源码仓库、原 PPT、参考图目录或个人开发者工具配置。**成品仍包含行程、集合地点和活动图片**，公开审阅前需确认这些可对外展示。
- 在 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。推送到 `main` 后会自动运行测试、构建和网页检查；全部通过才会部署到 Pages。也可在 **Actions → Publish H5 review to Pages → Run workflow** 手动重新部署。成功后分享部署返回的网址或其普通二维码，微信扫一扫即可打开，无需安装开发者工具。
- 若私有仓库因套餐限制不能开启 Pages，不必改源码可见性。获得公开成品的授权后，可将 `dist-review/` **的内容**放到单独的公开审阅仓库，Pages 选择 **Deploy from a branch → main → /(root)**。这种方式需要在更新版本时重新发布成品。普通 Pages 不是邀请制，拿到链接的人可能继续转发；如内容限内部，应使用带访问控制的托管。
